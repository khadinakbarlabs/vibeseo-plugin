# Content brief and optional draft

Read [shared rules](../vibesearch/references/workflow-common.md). Use [CLI guidance](../vibesearch/references/apify-cli.md) only for approved live collection.

1. Confirm the chosen keyword, site/audience, conversion goal, language/country and page type from existing context. For an existing page, use [content-refresh](../content-refresh/SKILL.md). Check verified page inventory for overlapping intent before proposing another URL.
2. Use supplied research or a bounded `scrape-google-serp` sample. Record capture date, locale, query, organic ranks and features. Review the actual top pages if authorized access exists. A title/snippet-only sample supports a preliminary brief, not claims about a page's full headings or factual depth. Never claim to have read pages you haven't read.
3. Identify the searcher's job, likely format and necessary questions. Describe common coverage and a specific addition this site can credibly provide: an original dataset, first-hand example, tested procedure, usable checklist, worked comparison or expert explanation. If there is no supportable contribution, prepare a research request rather than another generic article.
4. Assemble the [brief template](../vibesearch/references/report-template.md): intent, proposed URL, primary/secondary topics, 2–3 title options, H1, H2/H3 outline with section purpose, answer blocks where useful, facts/sources needed, original contribution, verified internal links or explicitly proposed candidates, CTA and author/reviewer needs.
5. Write a concise descriptive title and accurate summary; preview likely truncation. Character lengths are editorial checks, not guaranteed Google limits. Keyword use must read naturally. Don't chase a fixed keyword density, competitor word count or guaranteed E-E-A-T score. Suggest structured data only when it matches content actually present and its current eligibility can be checked.
6. If the user requests a draft, write it from the approved brief and provided/verifiable facts. Mark unresolved facts for review; don't invent statistics, testimonials, quotes, credentials, results or product capabilities. Give it a human, direct voice with useful examples. Cite sources rather than reproduce competitor passages.
7. Perform an editorial pass: answers the actual intent, contributes new value, factual claims supported, internal URLs verified, product promises accurate, and no unapproved publication. Finish with a review-ready brief/draft and missing evidence.

Writing a draft does not authorize publishing. Do not invoke a CMS or create new bulk pages automatically. Relevant source guidance: [Google people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).
