# Content refresh

Read [shared rules](../vibesearch/references/workflow-common.md). Reuse [brief guidance](../content-brief/SKILL.md) for evidence and drafting.

1. Obtain the actual page text/URL or an authorized export and its date. Reuse business context and goal. Ask for the page if it is necessary and missing; don't pretend a URL alone supplies its content.
2. Audit its current intent, title/H1, structure, answer quality, originality, facts, links, CTA and product claims. Preserve useful sections, existing URLs and first-hand evidence. Do not recommend a full rewrite by default.
3. Compare with supplied or approved sampled SERP data and relevant user-owned Search Console exports. Check matching windows/markets before treating a decline as real. Account for seasonality, tracking changes and differing query mixes; don't assert causation.
4. Produce a **Keep / Change / Add / Remove** table: exact section, evidence, proposed edit, expected user benefit and validation. Flag competing pages for review and preserve ownership/intent rather than merge or redirect without authorization.
5. If requested, draft the changed sections with citations and unresolved facts marked. Include title/meta options, verified internal-link suggestions, and visible-content-matching structured data recommendations where appropriate. No keyword stuffing, fabricated experience or bulk templated content.
6. Define an implementation checklist and a proposed matched follow-up observation window. Changes are proposals until the user applies/authorizes them. Indexing, rank movement and conversions are observations to verify later, not outcomes of producing an edit plan.

Output a focused refresh plan and requested draft edits. Use [report template](../vibesearch/references/report-template.md); hand matched ranking measurement to [rank-tracking](../rank-tracking/SKILL.md).
